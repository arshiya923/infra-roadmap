## Actual changes and reversal

The existing [single-area runner](../labs/ospf-routing.sh) still uses two FRR 8.4.4 routers and two endpoints in four owned namespaces. Its passive-transit fault withdraws adjacencies and remote routes with carrier up, then restores them. Two additional faults occur sequentially after that restoration:

1. Change only R2's namespace `net.ipv4.ip_forward` from 1 to 0. Both endpoint request/reply probes fail. Directly connected transit/gateway probes succeed, Full neighbors persist and selected installed OSPF routes/kernel next hops remain. Restore exactly 1; both endpoint probes succeed again.
2. Remove only the introduced server route `192.0.2.0/24 via 198.51.100.1`. This endpoint has no default route. Both endpoint exchanges fail while router Full neighbors, selected/kernel routes and R2 forwarding remain. Client/server gateways and R2-to-server-LAN controls succeed. Restore the exact endpoint route; its complete kernel route list matches the baseline and both exchanges succeed.

Linux documents that changing `ip_forward` resets IPv4 host/router defaults in that namespace. This disposable fixture restores the forwarding flag and verifies the stated protocol/route/probe conditions; it does not claim to restore every possible custom sysctl parameter. Do not interpret this fixture as a universal production rollback. See [Linux IP sysctl semantics](https://www.kernel.org/doc/html/latest/networking/ip-sysctl.html), checked 2026-10-09.

Each added probe retains its actual target, ping exit code and raw output. The successful controls have one received reply; failed endpoint probes retain nonzero exit status. This is settled bounded ICMP evidence. It does not measure application health, packet arrival at the server during the return fault, zero loss or convergence time. Known controlled interventions plus corroborating observations explain these fixtures; an isolated symptom in another network does not establish the same cause.

Run preparation and the lab using the path printed by [private FRR preparation](../labs/prepare-frr-runtime.sh), as described in [runtime requirements](ospf-runtime-foundation.md). Default invocation is inert help; explicit `--run` requires root network/mount capabilities. Fault changes are inside owned namespaces; no host forwarding, route, account, mount or routing service is changed. Normal cleanup and four deliberately interrupted paths are independently checked, including interruption while forwarding is disabled and while the endpoint route is absent.
