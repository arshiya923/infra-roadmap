The [standalone inspector](eigrp-neighbors-explorer.html) keeps R1 and R2 records at baseline, owned transit down, link restored before daemon restart and combined recovery. It reads source-hashed neighbor/interface/topology/configuration/RIB/kernel records and only the endpoint probes actually retained for each phase. Intermediate link restoration has no retained endpoint probe; later recovered probes cannot fill that gap.

The startup packet collection is displayed separately in every selected view. Seven fields retain source, destination, IP protocol, opcode, AS, sequence and acknowledgment. Discovery filtering requires opcode 5 with sequence and acknowledgment zero. UPDATE filtering uses opcode 1; acknowledgment filtering uses a nonzero acknowledgment, including UPDATEs carrying ACKs. Filters overlap. No flags, timestamps, parameter/authentication TLVs, checksum validation or complete route bodies were retained. These headers do not certify INIT, an exhaustive capture, timer expiration, rates or elapsed convergence.

Neighbor rows retain raw hold, uptime, SRTT, RTO, queue and sequence fields with units. SRTT concerns reliable-control acknowledgment timing, not application RTT or interface metric delay. The pinned raw uptime value is preserved rather than reformatted as Cisco output. Its zero SRTT/tiny RTO display is not zero physical latency or a universal timer bound. The interface report's Hello/Hold columns and additional contradictory Hello-interval line remain intact. Empty LAN peer count does not prove passive configuration. Rejected requested timer/passive settings remain unclaimed.

The actual fault is an owned link-down intervention, not hold expiry or passive suppression. Passing recovery explicitly restores the link and restarts both owned eigrpd children with exact unchanged configurations. [Rejected trials](eigrp-runtime-rejected-trials.json) retain unsuccessful link-only and requested-setting evidence. Actual peer, selected RIB, kernel and bidirectional endpoint ICMP observations belong to the [single-transit IPv4 experiment](eigrp-routing-lab-results.json), not an alternate-path or application benchmark.

Seven vendor blocks remain guided and unexecuted. Five inspect scoped configuration, neighbor/transport, active interfaces/counters, carrier/logs and destination-specific routing. Optional passive-transit suppression/restoration requires an existing prepared supported classic AS 100, an explicitly prior nonpassive owned interface, working original service and independent management. Restoration removes only that introduced setting. No global clear, process removal, timer/K/authentication change, static-neighbor repair, save or reload is supplied. Two additional blocks reference the shared actual private preparation and unchanged actual runner.

The evidence builder runs only against a passing report, preserving raw record equality and source SHA-256. The model validates fixed observer/checkpoint/filter identities and bounded retained data; returned values are fresh copies. Dynamic DOM content uses text nodes. Invalid selection hides stale evidence, and reset remains outside the hidden output. Model checks compare all 32 view/filter combinations to independent source parsing and preserve missing intermediate probes and real filter overlap.
