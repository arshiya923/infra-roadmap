# Batch 05 source review — accepted 2026-10-04

Routing/IPv6 extension: checked [iproute2 route operations](https://man7.org/linux/man-pages/man8/ip-route.8.html), [policy rules](https://man7.org/linux/man-pages/man8/ip-rule.8.html), [Linux forwarding sysctls](https://docs.kernel.org/networking/ip-sysctl.html), [IPv6 specification](https://www.rfc-editor.org/rfc/rfc8200.html), [Neighbour Discovery](https://www.rfc-editor.org/rfc/rfc4861.html), [address autoconfiguration](https://www.rfc-editor.org/rfc/rfc4862.html) and the PMTU reference below. Prefix specificity precedes metric in the stated single-table model; real policy context is explicit. Default-router discovery is separated from DHCPv6, on-link and autonomous flags remain distinct, and tentative/preferred/valid state is not collapsed into address presence. Forwarding sysctl writes in the executable lab occur only inside its newly owned router namespace. Static dual-stack success is not represented as automatic-configuration testing.

STP/MAC extension: [Cisco RSTP explanation](https://www.cisco.com/c/en/us/support/docs/lan-switching/spanning-tree-protocol/24062-146.html), [Cisco IOS XE STP guide](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/stp/stp-configuration-guide/m-stp.html), Linux bridge manual and kernel bridge documentation checked. Role is kept separate from state, stable path selection from convergence timing, and kernel-native STP inspection from userspace RSTP functionality. MAC learning remains source-based and VLAN-scoped; movement does not uniquely identify a cause.

VLAN/tag/trunk extension: reviewed [Linux bridge operations](https://man7.org/linux/man-pages/man8/bridge.8.html), [kernel bridge design](https://docs.kernel.org/networking/bridge.html), [IEEE 802.1Q overview](https://www.ieee802.org/1/pages/802.1Q.html), [historical Cisco frame format](https://www.cisco.com/c/en/us/support/docs/lan-switching/8021q/17056-741-4.html), and [current Cisco IOS XE trunk documentation](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html). Legacy CFI wording in historical framing references is not copied as the modern DEI name. Native-VLAN behaviour is kept platform-specific. The lab uses explicit tagged trunk memberships with no default PVID; same-prefix cross-VLAN hosts are deliberately a teaching counterexample, not a production design recommendation.

DHCP/NAT extension: [DHCPv4 RFC 2131](https://www.rfc-editor.org/rfc/rfc2131.html), [options RFC 2132](https://www.rfc-editor.org/rfc/rfc2132.html), [traditional NAT RFC 3022](https://www.rfc-editor.org/rfc/rfc3022.html) and [mapping/filtering distinctions RFC 4787](https://www.rfc-editor.org/rfc/rfc4787.html) checked. Lease fractions are explicitly a no-response teaching model. PAT ports are fixed examples, not a vendor allocator. Missing mapping does not imply an unmodelled firewall policy decision.

Transport/DNS extension: reviewed [UDP](https://www.rfc-editor.org/rfc/rfc768.html), [UDP application guidance](https://www.rfc-editor.org/rfc/rfc8085.html), [Python sockets](https://docs.python.org/3/library/socket.html), [DNS concepts](https://www.rfc-editor.org/rfc/rfc1034.html), [negative caching](https://www.rfc-editor.org/rfc/rfc2308.html), [DNS over TCP](https://www.rfc-editor.org/rfc/rfc7766.html) and [DNSSEC scope](https://www.rfc-editor.org/rfc/rfc4033.html). Original experiments distinguish API boundaries from wire packets and transport receipt from application commit. The DNS model preserves expiry and NXDOMAIN semantics without pretending to perform live resolution.
